# Paper Lifecycle

Use this checklist to decide what to update during each phase.

## 1. Idea

Capture in `idea/idea.md`:

- Research idea
- Scientific problem
- Research question
- Hypothesis
- Contribution target
- Highlights

## 2. Plan

Update `plan/research-scaffold.md` and `plan/milestones.md`:

- End-to-end workflow from data to analysis to output
- Milestones
- Decision gates
- Dependencies
- Risks and fallback routes

## 3. Data

Update `data/data-manifest.md`:

- Raw data inventory
- Provenance
- Permissions or access constraints
- Data dictionaries
- Known quality issues

## 4. Skills

Update `skills/skill-map.md`:

- Methods required
- Tools or libraries required
- Domain knowledge needed
- Missing capabilities
- Reusable skills that should be created or invoked

## 5. Literature

Update:

- `literature/literature-map.md`
- `literature/`
- `explanation/claim-ledger.md`

Organize literature by concept, method, dataset, result, or debate, not only by paper title.

## 6. Analysis

Update:

- `analysis/analysis-log.md`
- `analysis/`
- `output/result-ledger.md`

Record data processing and analysis methods. Do not perform final scientific interpretation in `analysis/`.

## 7. Output

Update:

- `output/result-ledger.md`
- `output/`

Store results produced by analysis: metrics, tables, intermediate findings, run outputs, model outputs, and statistical summaries.

## 8. Explanation

Update:

- `explanation/interpretation.md`
- `explanation/claim-ledger.md`

Integrate outputs into scientific interpretation, claims, limitations, alternative explanations, and narrative logic.

## 9. Visualization

Update:

- `visualization/figure-index.md`
- `visualization/`

Each figure or table should have source data, generation method, caption status, and manuscript status.

## 10. Writing

Use `writing/` for:

- Outline
- Section drafts
- Versioned manuscript drafts
- Abstract variants
- Title variants

Keep claims traceable. Do not add unsupported novelty claims.

## 11. Communication

Use `communication/` for human-facing interaction material:

- Plain-language project status
- Readable summaries of current work
- Human-facing diagrams or framework sketches
- Open decisions and questions for people
- Interaction notes, feedback, and follow-up requests

Do not treat communication files as source-of-truth scientific records. Link summaries back to data, output, explanation, literature, or manuscript files.

## 12. Other

Use `other/` for:

- Internal review notes
- Quality gate results
- Citation checks
- Logic and contribution checks
- Reviewer-style critique
- Final manuscript candidates
- Supplementary files
- Cover letter drafts
- Reviewer response drafts
- Revision maps

Keep reviewer comments and responses linked.
